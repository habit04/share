# DWG saving on Windows

In the Windows desktop edition, **SAVE** (Ctrl+S) saves to the drawing's current DXF or DWG file. **SAVEAS** (Ctrl+Shift+S) lets you choose **DXF Drawing** or **DWG Drawing** and a destination. A drawing opened from DWG keeps its DWG destination when portable saving is available; Save As lets you keep the original under a different name or switch formats.

The portable DWG writer is included in the Windows desktop app. Users do not need an installed copy of AutoCAD. If the writer is unavailable, JCad explains the error and you can continue saving DXF files.

JCad captures the drawing through its DXF writer and converts the snapshot privately. The native writer reopens the DWG to compare supported geometry and its typed metadata graph. A separate, mandatory check then reopens the emitted bytes through the bundled LibreDWG reader and compares retained metadata with the source DXF. Missing or changed data, incomplete projection, or native read/write errors refuse the save. Only accepted output replaces the destination atomically; an existing file is kept as `<name>.dwg.bak`. Successful ordinary Save binds the drawing to that destination and marks the captured revision saved. Edits made during conversion remain unsaved. Canceling or a conversion failure keeps the destination, working drawing and recovery records.

Saving cannot restore drawing content that JCad dropped, simplified or could not read during import. Review **IMPORTREPORT** and use Save As to preserve the original. Saving over the imported original asks for confirmation when the report records lost or unreadable content. A recovered DWG drawing retains a conservative overwrite warning because its DXF recovery snapshot cannot establish that all original DWG metadata survived.

For a separate copy, choose **J menu > Export > DWG copy**, or type **EXPORTDWG**. Exporting a copy does not change the working drawing's destination, dirty state, undo history or recovery checkpoint. Use Save to save the working drawing separately. Edits made during export are not included in the captured copy.

DWG saving is Windows only and emits AutoCAD 2018-format DWG (`AC1032`). macOS and Linux desktop updates are paused at 0.4.5; those editions and the browser save DXF copies. Closed DWG sheets are skipped by project-wide updates: open them in tabs to apply changes, then use Save. Autosave and crash recovery continue to use DXF snapshots, including for DWG working files.

The writer refuses unsupported retained records, including REGION, 3DSOLID, BODY, surfaces and proxy entities. Source checks reject unconsumed metadata fields, missing object identities and unsupported header values before conversion. The independent reader check compares retained OBJECTS records, named VIEW cameras, reactor/extension/XDATA records and nonvolatile source header variables, with typed references matched to their corresponding objects. These are bounded checks on exposed data, not lossless support for arbitrary DWG objects, proprietary classes, dynamic-block behavior or fonts. The [support matrix](SUPPORT-MATRIX.md) describes the drawing content JCad can hold. Save As to DXF preserves supported retained DXF records when DWG conversion is refused; keep the original for data already lost during import.

Supported named VIEW records retain the full camera: target and direction including Z, display center, width and height, twist, lens, clipping distances and mode flags. **VIEW Restore** displays planar orthographic model cameras looking along +Z at their source angle and switches to the Model tab. Paper-space, tilted, reversed and perspective cameras remain in retained data, but cannot be restored faithfully in this 2D editor. A future 3D editor is separate work.

Native FIELD/FIELDLIST records retain expressions, child fields, ordered object-reference vectors, evaluator settings and cached values. JCad reevaluates its supported filename, date and drawing-property expressions, plus supported sheet values when available. Other native evaluators, including object-property expressions such as a referenced line's length, keep their imported display/cache; JCad does not recompute them after geometry changes. **UPDATEFIELD** reports retained caches. Editing the displayed text manually detaches its native association and removes only its owned field tree; Undo restores it.

Retained objects follow the drawing through edits, undo and saving. Copying a connected selection remaps typed relationships inside each copy and clones owned dictionaries and fields, including clipboard copies between drawings. Deleting an object still required by a retained hard reference refuses the edit atomically. A missing hard dependency also stops saving with a specific explanation. Cross-document soft references that cannot be resolved are removed and reported. XRECORD 64-bit integers remain exact; strings, binary payloads and arbitrary handles remain opaque rather than being searched for references. Literal text such as `\U+0041` inside opaque metadata is not decoded into another character. File handles can change on export, so references from another file to particular handles are not guaranteed.

Rectangular layout viewports retain their planar orthographic top-view rotation when saving and reopening DXF or DWG. The view angle changes how model space appears on the sheet without changing model coordinates; the same angle applies to display, selection, panning, zooming and vector or raster plotting. To set it, unlock the viewport with **MVIEW Lock**, then use **VPTWIST** with an angle in degrees inside it, or select its frame on the paper and edit **Properties > Viewport > View rotation**. Positive angles turn the displayed model counterclockwise. Perspective views, tilted or reversed view directions and non-rectangular clipping remain unsupported and are reported as import approximations; saving cannot restore those original views.

Input and output are each limited to 128 MiB. The helper verifies a Windows Job Object 1 GiB process-memory limit before parsing. It accepts at most 250,000 DXF records, 20,000 blocks and 2,000,000 code/value pairs, with additional bounds on splines and hatch collections. Native metadata projection and the independent comparison are limited to 32 MiB, with at most 100,000 inventory objects. Conversion has a 60-second base deadline plus one second per input MiB, up to 188 seconds. Large valid drawings can be refused by these limits; save DXF when that happens.

Mixed control-point/fit-point splines keep the control-point curve used by JCad. Auxiliary fit points, tangents and construction settings travel in a bounded registered `JCAD_SPLINE_FIT` XDATA packet tied to that curve's geometry. Other CAD software may ignore that auxiliary metadata; it is not a promise of native fit-mode editing. The Windows native metadata projection preserves exposed application XDATA. A fallback reader can omit it and reports that limitation in IMPORTREPORT.

Published Windows packages require a valid publisher signature on the helper. An unsigned local development build may be blocked by Windows Security. Use a verified signed build for testing on such a system and leave Windows Security enabled.
